# 淘宝千牛上架技能 · 同事上手（3 步）

> 这个技能做一件事：把**素材包**填进淘宝/千牛的发布页，填到「提交前」为止。
> **它永远不点「提交宝贝信息」**——最后一步由你人工核对后自己点。

---

## 前提（缺一不可）

| 依赖 | 说明 |
|---|---|
| Windows + Google Chrome | 装好即可，不用装任何浏览器驱动 |
| Node.js | 技能**自带** playwright-core（约 13MB），**不用** `npm install` |
| 你自己的千牛账号 | **一店 = 一个千牛账号 = 一个独立 Chrome + 一个独立端口** |

> 本技能**不代登录**、不碰账号密码。

---

## 第 1 步：解压 + 登记你的店

解压到（推荐）：

```
C:\Users\<你的用户名>\.config\mimocode\skills\taobao-product-listing\
```

然后改同目录下的 `config.json` 这四项：

```json
"chrome_profile": "C:\\Users\\<你的用户名>\\.openclaw\\chrome_taobao",
"default_port": 9120,
"shops": {
  "你的店名": { "port": 9120, "note": "千牛已登录" }
}
```

- **一店一个端口**：同时开两家店就是 9120 / 9121 两个 Chrome。
- `chrome_profile` 换成你自己的路径（第一次起浏览器会自动建）。
- 多人多店时 `preflight.ps1` 不传 `-Shop` 会把登记的店**逐家查**。

---

## 第 2 步：起浏览器 + 自己登录千牛

```powershell
powershell -File "<技能目录>\scripts\open_browser.ps1"
```

在弹出的 Chrome 窗口里**登录千牛**（工作台 `https://qn.taobao.com/home.htm/QnworkbenchHome/`）。

**⚠️ 把窗口最大化**（原因见文末「为什么要求最大化」）。

---

## 第 3 步：一条命令跑

素材包要长这样（**素材包由你自己提供**）：

```
<素材包>\
  商品信息.xlsx                    ← 含「淘宝」sheet，第 5 行起填商品
  淘宝\<商品标识>\
    1比1主图\   3比4主图\   宝贝详情\   规格图片\   SKU搜索主图\
```

跑：

```powershell
powershell -File "<技能目录>\scripts\run_listing.ps1" `
  -ProductId "<商品标识>" `
  -CatId <catId> `
  -Cat "居家布艺 > 地毯" `
  -Shop "你的店名"        # 多店时必填；单店可省（会自动取 config.json 里那一家）
```

**参数**

| 参数 | 说明 |
|---|---|
| `-ProductId` | 商品标识（= 素材包 `淘宝\<标识>` 的目录名；也是 `output\<标识>` 的名字） |
| `-CatId` / `-Cat` | 类目 catId + 完整路径（路径用 ` > ` 分隔） |
| `-Shop` | 店名，对应 `config.json` 的 `shops`。**同时决定用哪个 CDP 端口** |
| `-Port` | 直接指定端口（覆盖 `-Shop` 推导）。只测某端口时用 |
| `-ProductDir` | 顺带把商品素材目录交给 preflight 检查 |
| `-MainLimit` | 1:1 主图本次传几张（默认 0 = 目录里几张就传几张） |
| `-DetailBatch` | 详情图每批张数（默认 20；**一批喂太多会被平台截断**） |

> ⚠️ **不用 `-Shop` 也不给 `-Port` 且登记了多家店时，脚本会直接报错停下**（不猜——猜错就是把货填到另一家店）。
> 端口会解析出来并通过 `TB_PORT` **下发给每个子脚本**；不指定时按 `config.json` 的 `default_port`。

**素材文件命名要求（重要）**

| 目录 | 要求 |
|---|---|
| `1比1主图\` | 任意名，按文件名排序取前 N 张；**越大越好，单图 ≤3MB** |
| `宝贝详情\` | 任意名，按文件名排序（建议 `01_…` 编号）；**一批 >20 张会被平台截断**，脚本会自动分批 |
| `规格图片\` | 推荐 `<商品标识>规格图-<颜色>.jpg`。**更稳的做法**：在素材包 Excel 的「规格图片文件名」列里逐 SKU 写明文件名（脚本优先按它找图）。支持 jpg/jpeg/png/webp/bmp/gif |
| 颜色值 | 规格图的「颜色」要与「颜色分类」的值能对上（长营销文案也行，走 Excel 映射那条路） |

> 规格图**不要**只写 `卡其色.jpg` 就丢进图片空间了事 —— 图片空间里可能有别的商品的同名图，脚本靠**文件名唯一性**定位。

例（已在用的一个真实商品）：

```powershell
powershell -File "<技能目录>\scripts\run_listing.ps1" `
  -ProductId "DT-雨棚消音垫-1057991085138" `
  -CatId 50000582 `
  -Cat "居家布艺 > 地毯" `
  -Shop "示例店"
```

## 它会做什么 / 不会做什么

**会**：入口选类目（走「搜索发品」）→ 标题/属性/货号 → SKU 批量导入（官方模板）→
1:1 主图 → 宝贝详情图 → 规格图（按颜色挂）→ 核对清单 → 保存草稿。

**不会**：
- ❌ 点「提交宝贝信息」（**这是硬规矩**，永远留给你点）
- ❌ 代登录、碰账号密码、绕验证码
- ❌ 改价/库存/下架/活动/订单/客服

---

## 预期输出

最后一行是 `DONE: all green`；哪一步没过会列在 `DONE: failed steps` 下面。

跑完会打印核对清单，逐条对照素材包的期望值：类目 catId / 标题 / 品牌 / 货号 / 一口价 /
总库存 / SKU 行数 / 规格区 / 主图空槽 / 详情图数 / 页面报错。

**别只看最后一行**：清单里任何一条 ✗ 都值得停下来看一眼。

## 三个已知问题（先看，免得以为技能坏了）

**1）登录态会过期。**
症状：`★ 开不了工：端口 9120 通了，但**停在卖家登录页**`。
处理：在那个 Chrome 里重新登一次千牛，然后重跑。技能不代登录。

**2）详情图那一步可能停在「19/20」。**
淘宝图片空间「上传后自动全选」**不是 100% 确定**的（有时 20/20、有时 19/20）；
如果差额补不上，脚本会如实报出来，详情图数量就会比预期少几张。
处理：补跑一次详情图那步，或手工在页面里补选。
**这是已知问题，暂未修**（不影响其它步骤）。

**3）窗口别拖小。**
见下。

**4）保存草稿被「草稿数量上限」拦住。**
淘宝对草稿箱/该类目的草稿数量有上限，超了就不让存。
处理：去「千牛 → 商品管理 → 草稿箱」删掉旧草稿（或换类目/换店）后重跑这一步。
脚本会把这个情况**单独识别并说明**（不会只丢一句"保存失败"）。
⚠️ 存成功之前，页面上填的东西**只活在当前页面里**：别刷新、别关页。

**5）某个属性在页面上填不上（比如品牌被打字进去却读回为空）。**
多半是页面上还停着一个浮层挡住输入框。整链现在会在填属性前、详情图之后各跑一次
`close_dialogs.js --all` 清扫所有残留弹窗；品牌那一步在被遮挡时还会**先关遮挡物、重新取坐标**再点。
如果仍失败，把日志里那一步的「读回」贴出来即可定位。

---

## 为什么要求窗口最大化

素材面板（淘宝的「图片空间」）是**按视口尺寸渲染**的：

- 窗口小 → 列表一屏只显示几行，脚本要多滚很多次；
- 按钮会贴近窗口边缘，脚本按坐标点击容易落空（实测 1203×917 的视口就比 1920 宽时更脆）。

**不需要固定某个分辨率，只要别把窗口拖小**（最大化即可）。

## 出问题先跑这两条

```powershell
powershell -File "<技能目录>\scripts\preflight.ps1"   # 环境 / 端口 / 千牛登录态自检（按店）
powershell -File "<技能目录>\scripts\selftest.ps1"    # 技能自身完整性（BOM / 语法 / 门禁 / 依赖）
```

`preflight` 会明确告诉你是「端口不可达（Chrome 没开）」还是「停在登录页（登录态过期）」，
`selftest -Quick` 跳过端口部分、只查文件本身。
