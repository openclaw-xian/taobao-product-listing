# 运维笔记：事故复盘 + 改代码前后的必做动作（淘宝技能）

> 这份是**给以后改这个技能的人（或 agent）看的**。教训都来自真实踩坑，不是通用建议。
> 逐步操作手册在 `references/playbook.md`，门禁在 `SKILL.md`，完整交接在 `HANDOVER.md`。

## 一、改代码前后的必做动作

1. **改大文件前先备份**到 `_backup\<文件名>.<时间戳>.bak`（本技能已建这个目录）
2. 改完**跑 `scripts/selftest.ps1`**（退出码 0 才算过）：它会机械检查 `.ps1` 的 BOM、
   **脚本是否被截断**、语法、门禁编号连续、必备文件、config 结构、playwright-core 来源
3. 门禁/流程写进 `SKILL.md` 时要**编号连续**（selftest 第 4 项会查，并检查「门禁 N」反向引用不越界）
4. 现场实测到的选择器变化 → 更新 `references/RECON.md`（**它比 playbook 权威**）

## 二、事故复盘

### A. 一行「顺手」的 python 把 `preflight.ps1` 截成 3 字节（2026-10-10）

- **症状**：批量补 `.ps1` 的 BOM 时写了个一行式：
  `[open(f,'wb').write(bom + open(f,'rb').read()) for f in files if not open(f,'rb').read().startswith(bom)]`
  → 之后再跑 `preflight.ps1`：**没有任何输出、退出码 0**（只剩 3 字节 BOM 的空脚本）。
  文件大小：`preflight.ps1` 3 字节（其它三个因为有 BOM 被 `if` 跳过，侥幸没动）。
- **根因**：**同一表达式里既 `open('w')` 又 `.read()`** —— 求值顺序里 `open(f,'wb')` 先执行、当场把文件截断，
  随后 `open(f,'rb').read()` 读到的是**空文件**，于是只写进了 BOM。这是 Python 求值顺序的经典自杀式写法。
- **代价**：一个关键脚本（开工前自检）静默消失；而且它**失败得很安静** —— 空脚本 = 成功退出。
- **修法**：重写该文件；并把这条做成机械检查 —— `selftest.ps1` 现在有 **1b) 脚本非空（防自我截断）**：
  `scripts/*.ps1|js|py` 小于 200 字节就报 FAIL 并提示从 `_backup` 恢复。
- **教训**：
  ① **要读要写先分离**：`data = open(f,'rb').read()` 一行，`open(f,'wb').write(...)` 另一行。永远别写在一句里。
  ② **批量操作脚本别用一行式**：写进临时 `.py` 文件再执行（本项目一贯做法），可读、可复查、可复用。
  ③ **「成功退出」不等于「干对了」**：空脚本/空产物会用退出码 0 骗过自动化 ——
     所以要有「文件大小/产物存在性」这类**结构检查**兜底。

### B. `"shops": {}` 空对象会变出一个「假店」（2026-10-10）

- **症状**：`config.json` 里 `shops` 还是空对象时，`preflight.ps1` 报
  `[] 端口 0 不可达 —— 请用 --remote-debugging-port=0`（店名是空的、端口是 0）。
  改成过滤之后又发现：`if ($e.shops)` 判空对象为**真**，于是走了「有店」分支 → 一个端口都没查。
- **根因**：PowerShell 里 **空 `[pscustomobject]`（`{}` 经 `ConvertFrom-Json` 的结果）不是「空集合」**，
  它 truthy；而 `@($obj.PSObject.Properties.Name)` 在无属性时返回的是 **含一个 `$null` 的数组**（长度 1！）
  → 于是「店名 = $null、端口 = `[int]$null` = 0」的假店被造出来。
- **修法**：`$names = @($obj.PSObject.Properties.Name | Where-Object { $_ })`（过滤掉空/`$null`），
  并且**按 `$names.Count` 分支**而不是按 `if ($e.shops)`。
  `resolve_env.ps1` / `preflight.ps1` / `selftest.ps1` 三处同源写法都要加过滤。
- **教训**：
  ① PowerShell 里判「有没有东西」要用**集合长度**，不要用对象真假；
  ② `@($null)` 的长度是 1，这是很多「幽灵元素」bug 的源头；
  ③ 一份配置在**没填**的时候也应该跑得通（跑到「未登记店铺，用 default_port」那条兜底路径），
     否则「填之前不能自检、自检之前不知道要填什么」——死锁。

### ⚠️ preflight 把「跳登录页」误判成「已登录」（2026-10-10 修）

- **现象**：关机后重开 Chrome，页面全跳 `login.taobao.com`，但 `preflight.ps1` 仍报「千牛/卖家页 1 个（已登录）」，
  差点让我在未登录状态下跑自动化（第一轮就是级联项全空、摸不着头脑）。
- **两个原因**：① 登录页 URL 的 `redirectURL` 参数里带着 `item.upload.taobao.com` → 整串 `-match` 命中卖家域；
  ② `loginmyseller.taobao.com` 含 `myseller` 子串 → 命中 `myseller\.taobao\.com`。
- **修法**：**只匹配 host**（正则取 `^https?://([^/?#]+)`），且 host 含 `login` 的一律不算卖家域。
- **教训**：判「登录态」这类事**别 match 整条 URL** —— 查询串（`redirectURL`、`from`…）里什么都可能有，
  一定要按 host / 路径结构化判断。

## 三、环境类坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `.ps1` 必须 UTF-8 **带 BOM** | PS 5.1 按 GBK 读 → 中文串烂、报「意外的标记」 | 用编辑器 / Edit 工具改完**一定**补 BOM；`selftest.ps1` 第 1 项专查这个 |

| 淘宝发布页改版 | 笔记里的选择器失效 | 以现场 DOM 为准（`SKILL.md` 门禁 3），顺手更新 `references/RECON.md` |

| `input.value` 残留 | 属性看着填上了，其实没选中 | 必须真点下拉选项（门禁 12） |

## 五、⚠️ 最贵的一次教训：**刷新 ≠ 安全**（2026-10-10 实测）

**经过**：图片空间面板卡在「已选中待确定」状态（点什么都无效），我为了让面板复位，在 `scripts/tb_upload_detail.js`
里加了 `page.reload()`。刷新后读回：**标题空、SKU 表没了、属性全空**（页面上也没有「最后保存于」）——
即**这个页面从未被保存过**，刷新把刚填的东西全冲掉了。

**背景认知纠错**：先前在 `RECON.md` 记过「淘宝表单会自动存草稿（与抖店不同）」，
那是基于**某一次**看到底部「最后保存于 13:53」。**事实是：并非每步都自动存** ——
没触发保存时，刷新/关页 = 内容全丢。

**规矩**：
1. **不要用刷新复位**（要复位就关掉弹层/重开页）。
2. 一段自动化跑完，**先点「保存草稿」**（门禁 2 只禁「提交宝贝信息」，**「保存草稿」是安全的**），再动别的。
3. 重填不心疼（脚本都在）：`tb_fill_basic.js` → `tb_import_sku.js` → `tb_upload_main.js` 按顺序跑回来即可
   （本次实测：标题 30 字 / 货号 / 成猫 / **SKU 72 行对账 0 缺 0 多** / 一口价 83.8 / 总库存 7200 全部复现）。

## 四、决策类教训（别重犯）

### 入口：**「以图发品」看着省事，实测更费事**（2026-10-10）

以图发品的卖点是「AI 推荐类目 + 自动铺图」，但实测**它会把上传的主图自动铺进「宝贝详情图」**：
传 5 张 1:1 主图进去，详情区被塞进同一批 5 张（编号 1–5）。我们的口径是「主图 5 张 + 详情 20 张各自独立」，
于是「省下的选类目」被「先删详情图、再重铺 20 张」抵消掉 —— 用户当天拍板**弃用**。

- **教训**：平台的「自动化便利」要拿**我们自己的口径**去验，不能拿「页面上少点几下」当收益。
- **落点**：`SKILL.md` 门禁 19（入口只走搜索发品）；脚本 `scripts/tb_enter_form.js`。

### 「下一步」灰着 ≠ 叶子没选中（2026-10-10）

类目级联点完三级、三个 `li` 都 `selected`、底部也显示了路径，但「确认，下一步」**仍然是灰的** ——
我第一轮据此写了「叶子没提交成功」的错判。**真实原因是「品牌必填未选」。**

- **教训**：按钮 `disabled` 时，先找**这一步还有哪个必填没填**，别急着重做上一步。
- **落点**：`SKILL.md` 门禁 20（顺序：类目 → 品牌 → 下一步）。
- 附带一条：类目页的品牌下拉是**检索型**（选项为 `div.options-item`，首屏 14 项、硬滚滚不出更多），
  **必须用它自带的搜索框过滤**；这和表单页 `#sell-field-p-20000` 的长列表滚法不是一套。

### 「规格图没传上」常常是假的：虚拟滚动 + 图片懒加载（2026-10-30 实测）

**经过**：MZB-001（`50003280`，单列规格 54 个值）被报「规格图没上传完成」。第一次读回确实只 36 张正常，
**第 37–54 格 18 张 `complete=false / naturalWidth=0`**，看着就是没传。把图位滚进视区停三秒再读：
**54/54 全部 `naturalWidth=320`**，`src` 只有 6 个、各出现 9 次（6 色 × 9 尺寸，同色共用同色图 = 正确语义）。
用户当场也改成「现在有了，刚刚没有」。

**坑有两层**：
1. 抽屉的 DOM 一直挂着全部 54 个图位（尺寸也正常），**只有 `<img>` 是懒加载** —— 于是
   「图位总数 / 已有图 / 空图位」三个计数全绿，但你真看有没有图，得把它滚到。
2. 抽屉的滚动方式**不固定**：同一页面实测过两种形态 —— 内部滚动（抽屉高 915px、内层 `overflow-y:auto`）
   和全高展开（抽屉高 3678px、**没有任何内滚容器**）。只写「滚内部容器到底」的兜底，在全高形态下
   **静默失效**（找不到容器，什么也没滚，还继续往下读）。

**规矩**：
- 判规格图有没有传上，用 **`naturalWidth > 0`**，不要只看有没有 `<img>`。
- 兜底用**逐个图位 `scrollIntoView`**（分批、每批等 600ms），不要依赖某一种滚动容器。
- 工具已改：`tests/verify_spec_images.js` 先 `primeImages()` 再读，输出
  `加载成功 / 加载失败 / 唯一src数 / src分布`；抽屉没开直接提示并 `exit 3`，不再静默给空结果。

### `sell-field-p-<pid>` **不是可靠的属性选择器**（2026-11-10 实测）

墙纸类目 `201802801` 的「类目属性」区实际有 **7 个属性**（品牌 / 计价单位 / 功能 / 适用空间 / 风格 /
是否定制 / 采购地），但只有 **5 个**带 `sell-field-p-<pid>` 这个 id ——「是否定制」和「采购地」没有，
而**「采购地」还是必填**。

- 只按 `[id^="sell-field-p-"]` 读：属性少时看不出来（猫抓板 17 个全带 id，一切正常）；
  墙纸类目就只剩 2 个（还没展开折叠时），展开后也只到 5 个。
- **正确口径**：`.sell-component-info-wrapper-wrap` + 用「类目属性」标题到「销售规格」标题的
  **纵向坐标区间**圈定，再取每个容器文本的第一段作属性名、看有没有 `*` 判必填。
  （实测：区间 `[551 → 1055)` 里正好 7 个容器）
- 区间法会圈进「销售规格」这个区标题（y 落在上界内）→ 要显式排除，否则生成器会在 R2 里出现两列同名。

**影响面（未修，需要单独验证）**：`scripts/pack_meta.js` 已改用区间法；但
`scripts/tb_fill_basic.js` 和 `scripts/tb_checklist.js` 仍只用 id 前缀读 → 这类无 id 的属性
**读不到也填不上**，如果是必填（如「采购地」），提交时会被平台拦。已跑通的两个类目（猫抓板 17 个全带 id、
地毯 11 个全带 id）不受影响。

### 类目页「确认，下一步」永远灰 → 直连 publish.htm（2026-11-10 实测）

墙纸类目 `201802801`：类目页有 **5 个必填**（计价单位 / 采购地 / 图案 / 材质 / 面层工艺），
`tb_enter_form.js` 全部报「找不到容器」→「确认，下一步」永远是灰的，流程卡死在类目页。

- **兜底**（已加进 `tb_enter_form.js`）：直接 `goto`
  `publish.htm?catId=<id>&fromAICategory=true&keyProps=%7B%7D&fromAIPublish=true&newRouter=1`
  实测落地 `在表单 = true`、`catId` 正确、类目属性 7 个都读得到 —— 那批必填交给表单页处理。
- **副作用**：直连不会带上类目页选过的品牌 → 置 `brandSkipped = true`，品牌由 `tb_fill_basic` 在表单页填。
- **配套**：`run_listing.ps1` 里**入口步失败立即 `break`**。原先"失败也继续跑"的写法，
  在入口失败时会让后 14 步全部跑在**上一个类目的页面**上（实测墙纸：全跑在猫抓板上，
  只有核对清单报出「catId 读回=50003280 期望=201802801」）。

### 「数值 + 单位」组合属性要拆两列（2026-11-10 实测）

墙纸类目的「计价单位」控件类型是 `taoSirProp`，真实素材包里是**两列**：
`计价单位`（数值，如 `1`）+ `计价单位(单位)`（如 `卷`）。只给一列的话，填「其他」会被判
`option_not_found`（该类目没有「其他」这个值），留空又进不了 `product.json`。

`pack_meta.js` 现在会读出属性的 `kind`，`make_pack_skeleton.py` 据此把 `taoSirProp` 拆成两列。

### 草稿箱上限的说法（2026-11-10 实测）

平台拦住保存时的原文是「**草稿箱最大保存 10 条草稿**，如果继续保存，请删除不用的草稿」——
原来的识别正则只认「上限/最多」，漏了「最大保存」→ 被误报成"未识别的原因"。
`tb_save_draft.js` 已补上（现在会直接说"保存被草稿数量上限拦住，不是技能填错"，并给出删草稿的路径）。
技能**不代删**草稿。
