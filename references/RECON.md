**★ 属性区的规律（好用的结构判据）**：
每个属性是一个 `div[id="sell-field-p-<属性id>"]`，**容器 class 里直接写了控件类型**：

```
<div class="… sell-component-item-prop-item <控件类型> label-vertical" id="sell-field-p-<id>">
```

| 容器 class 片段 | 控件类型 | 填法 |
|---|---|---|
| `combobox` | 可搜索下拉（品牌/主体材质） | 原生 setter 写关键词 → **必须点下拉选项** |
| `select` | 单选下拉 | 点开 → 选一项 |
| `checkbox` | **多选** | 勾选（可多个） |
| `input` | 文本直填 | setter + input 事件 |
| `taoSirProp` | 「淘先生」类数字/单位字段（展开长度/宽度/厚度/重量…） | 填数字，注意**单位在旁边** |

### 2026-10-10 · **实测：AI识别导入 认我们的表（但只认到 1 个维度）**

实验：用 `scripts/tb_build.py` 把 MZB-001 造成本地 SKU 表（**72 行**，列
`颜色分类 | 款式 | 价格 | 库存 | 商家编码`）→ 打开「批量导入」→ `setInputFiles` 上传 → 点「确认识别」。

| 环节 | 实测 |
|---|---|
| 打开弹窗 | 「批量导入」按钮（真实点击即可；若弹窗已开着，`page.click` 会超时，属正常） |
| 上传 | `input[type=file]`（全页 1 个）`setInputFiles` 成功 → 弹窗里显示 `sku_import.xlsx 6.88 KB` |
| 按钮状态 | 上传前 `确认识别 disabled=true`；上传后 **`disabled=false`** ✓ |
| **识别结果** | 平台原文：「**已成功识别 1 个销售属性**，确认无误后请点击添加。平台会根据您的实际上传情况解析更多 sku 维度信息并回填，请您在销售规格列表中仔细检查」 |
| 认出来的维度 | **颜色分类** = 6 个值：`米白 卡其 黑色 浅灰 深蓝 深棕`（**与我们的数据完全一致 ✓**） |
| **没认出来的** | **「款式」（12 个尺寸）没被当成第二个维度** —— 它在问「在当前规格后添加」 |
| 后续入口 | 弹窗里给的是 **「在当前规格后添加」 / 「取消」**（即：一维一维来） |

**结论（当前）**：AI识别导入**可用**，能省掉「逐个规格值」的功夫，但**多维度要分步**，
或者得换成它认得的列名/格式。**下一步要试的假设**：
① 把两个维度**塞进一列**（照源表 `颜色分类` 的写法 `米白-宽30cm长1米`，看它会不会自动拆成 2 维）；
② 换列名（`尺寸` / `尺码` / `规格`）看能不能认作第二个维度；
③ 直接走「在当前规格后添加」分两次喂（第二次只给 款式+价格+库存）。

  → 正确配方 = **每批 ≤20 张，各自走完「上传 → 自动全选 → 点确定」**（实测 20 张 → `确定（20）` → 详情 3→24；
  再 6 张 → `确定（6）` → 24→30）。`--skip N` 用来做第二批。
- **上传完会自动全选**（面板行为），但**延迟生效**：抢在它生效前把「已选 20」误读成 0，
  就会去逐张点 → **点已勾选的框 = 取消勾选**（看起来就是"一张张在取消"）。
  → 上传后**先等计数稳定**；一旦计数齐了**立刻短路去点「确定」**；已勾选的卡片**绝不点**。
- 详情图卡片的可点目标是**右上角的 `.next-checkbox`**，不是文件名标题层（点标题选不中，白点 26 次）。
- **搜索框那条路会让 iframe 重载**（「输入文件名 + 回车」后每张都抛 `Frame was detached`）→
  默认走「扫可见卡片 + 点勾选框」，只有 `--search-fallback` 才用搜索。
- 规格图「批量填充规格主图」面板**自己写着口径**：**「选中右侧销售属性值后，点击左侧图片」**。
  两层规格下右侧是**独立的颜色值**（无 `-尺寸`），且**默认只选中第 1 项** ——
  原 `listValues()` 用 `startsWith(颜色 + '-')` 一个都匹配不上 → 从没点过右侧 →
  每次点图都填到默认选中的第 1 个颜色上 → **9 个规格图槽被同一张图覆盖**（唯一 src 只有 2 个）。
  → 正确做法：**先把该颜色在右侧选成唯一选中（多选就先取消别的），再点左侧那张图**；
  跑完必须用 `tests/verify_spec_images.js` 核对 **9 个图位的 src 互不相同**（只看计数会被骗）。

### 页面 / 草稿
- ⚠️ **`page.reload()` 会把发布页清空**：标题 / 属性 / 99 行 SKU / 主图 / 详情图**全丢**，
  页面变成一张全新空表单（草稿在箱里但**不会自动回填**）。`tb_upload_detail.js` 的 ⓪ 复位原来就
  写着"刷新后自动恢复"并且真的刷新 → 白干一小时。**已改成：绝不刷新**（能点「确定(N)」就点，否则停手报人）。
- 本店草稿箱 2026-10-13 起**可以写入**（`最后保存于` 时间戳会跟着变、无「最多 10 条」拦截）。
- **「最后保存于…」是首次保存成功后才出现的标记**；点「保存草稿」的坐标会因页面懒加载回流而**过期**
  （整链里点空过一次，同坐标手动再点却成功）→ `tb_save_draft.js` 改成
  「重取坐标 → 点 → 轮询等标记 → 没等到就换元素点击再试，最多 4 轮」。
- 写 `.ps1`（含**临时包装脚本**）必须 **UTF-8 带 BOM**：没 BOM 时 PS 5.1 按 GBK 读，
  类目里的中文会变成 `灞呭甯冭壓` → 级联点不中 → 整链从第 1 步就崩（这次亲自踩到）。

### 2026-10-14 · 开工前守卫（`scripts/guard.js`）：让「没浏览器 / 没登录」不可能被忽略

**起因**：调试口的 Chrome 没开时直接跑 `run_listing.ps1` → 16 个步骤逐个抛
`connect ECONNREFUSED 127.0.0.1:9120`，看起来像技能坏了，其实只是浏览器没起；
更早那轮还因为**登录态过期**（隔天）白跑一整轮。根因是：`preflight.ps1` 会做这些判断，
**但只有"记得先跑它"时才起作用** —— 单跑某个脚本时连这点检查都没有。

**做法**：新增 `scripts/guard.js`，**18 个会连浏览器的脚本全部在 `connectOverCDP` 之前调用它**
（`await guardCheck(PORT)`）。判据与 `preflight.ps1` 第 4 节**逐字一致**：

| 情况 | 输出 | 退出码 |
|---|---|---|
| 端口不通 | `端口 9120 不可达 —— 该店 Chrome 没开、或没带 --remote-debugging-port=9120` | 2 |
| 通了但没有卖家页 | `没有淘宝/千牛页面` + 该打开哪个地址 | 2 |
| 停在登录页 | `停在卖家登录页 —— 登录态过期了，请在该 Chrome 里登录千牛` | 2 |
| 正常 | 静默返回，继续跑 | 0 |

`TB_SKIP_GUARD=1` 可跳过（只给 `tests/` 下的探针用）。

**判据踩坑（必须按 host 白名单，不能图省事）**：
- 卖家域 = `qn.taobao.com|item.upload.taobao.com|myseller.taobao.com|sell.taobao.com|sycm.taobao.com|i.taobao.com`，
  且 **host 含 `login` 的一律不算**（`loginmyseller.taobao.com` 含 `myseller` 子串会被误命中；
  登录页 URL 的 `redirect_url` 参数里也带着 `item.upload.taobao.com`）。
- **不能**用「任何 `*.taobao.com` / `*.tmall.com` 都算卖家域」：实测 `main.m.tmall.com`
  （第三方 cookie 弹窗页）会被误判成"已登录"，于是守卫放行、真跑起来才发现没登录。

**编排侧**：`run_listing.ps1` 开工前也先跑 `preflight.ps1`，不通就**1 秒内停下**并打印怎么起浏览器
（实测 1 秒 exit=1，不再白跑 13 分钟）。

**待补（不强求）**：判据目前只看**标签页 URL**。若哪天淘宝把「未登录」做成"卖家 URL 不变、页内弹登录框"，
URL 判据会失效 → 那时要在 guard 里加**页内 DOM 判据**（例如读店铺名 / 找登录框）。
